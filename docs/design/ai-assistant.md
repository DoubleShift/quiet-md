# 右侧栏 AI 助手：设计（草案，待定方向）

状态：**讨论稿**。第 7 节列出要用户拍板的问题，定了再实现界面。优先级排在设计系统和数据表之后，不急（2026-11-23 用户定）；现在只推进 CLI 和不碰界面的 `crates/agent` 原型。

目标：在应用右侧加一个 AI 助手面板，用**用户自己的** Agent 读、找、改文档库里的内容。**从一开始就按多 Agent 设计**：用户原话是「后面支持尽可能多的 Agent，可能不止支持 Codex 和 Claude」。应用不付模型费用，也不经手用户的账号凭据。

依据：
- 「右侧栏 AI 助手集成」会话的讨论和实验（2026-11-22）：实验在分支 `exp/acp-latency` 的 `experiments/acp-latency/`，README 里有完整数据。
- 社区对 ACP 的评价调研（同一会话，2026-11，来源是 Hacker News、各项目 GitHub issue、Zed 和 OpenAI 的博客与文档；Reddit 和 X 没能访问）。
- `quiet` 命令行（PR #396，`docs/design/CLI.md`）。
- 多根工作区（`docs/design/workspaces.md`）。

## 1. 接哪些 Agent，用什么协议

### 结论：一个统一接口，两类后端

应用内部定义**自己的** Agent 接口（`crates/agent` 的 `Backend`）：会话、流式消息、思考、工具调用、审批、取消、状态、预热。界面只认这个接口，不认任何一家的协议。后端分两类：

| 后端 | 适用的 Agent | 接法 |
|---|---|---|
| **ACP（通用后端）** | 原生支持 ACP 的 Agent：Gemini CLI 等（ACP 生态已有约 50 个 Agent） | 起 Agent 的 ACP 模式子进程，JSON-RPC over stdio。接一次，覆盖一批 |
| **原生后端：Codex** | Codex | **`codex app-server`**（JSON-RPC over stdio），不经 codex-acp |
| **原生后端：Claude Code** | Claude Code | `claude -p --input-format stream-json --output-format stream-json`。原生安装版没有 Node 依赖。这个协议**不是公开契约**，要锁版本：检测 `claude --version`，只对验证过的版本范围启用，其他版本提示 |
| 以后，另议 | 内置 AI（自带 key / 本地模型） | OpenAI 兼容接口，也套同一个 `Backend`；见 7.4 |

规则：
- **原生支持 ACP 的走 ACP**。只有「不原生支持 ACP、又足够重要」的 Agent 才写原生后端，现在只有 Codex 和 Claude Code 两个。ACP v2（2026-11-20 Preview）修了中途插话、单独取消、断线回放、审批信息不全这些 v1 的问题；通用后端按 v2 写，v1 能跑的先跑，有缺的能力在界面上降级（比如不能中途插话就只给「停止」）。
- **不内置 Node**。需要 Node 适配器的 Agent（例如各种 `*-acp` npm 包），只用用户已经装好的，或者适配器自己发的独立二进制。应用不带 Node 运行时，也不替用户 `npm install`。
- **应用不碰任何凭据**。每个 Agent 都用它自己的登录（用户在 Agent 自己的命令行或界面里登录）。应用只负责起进程和说协议。
- 每个后端声明自己的能力（能否中途插话、能否单独取消、有没有思考流、能否设只读沙箱），界面按能力显示；第 4 节的安全要求是硬条件，做不到「只读、不能执行命令」的 Agent 不能接（或只能在用户明确放开后以受限模式使用，见 7.6）。

### 为什么 Codex 用原生后端，不走 codex-acp

实验数据（6 轮中位数，M 系列 Mac）：

| | 直接用 app-server | ACP（codex-acp 2.9.0） |
|---|---|---|
| 启动到首轮第一个字 | 约 11.0 秒 | 约 11.1 秒 |
| 第二轮：发出到第一个字 | 1.84 秒 | 1.92 秒 |

1. **ACP 本身不慢**：探针拆出来，进出 codex-acp 各 1–2 毫秒，多一层 Node 进程启动约慢 80 毫秒。
2. **慢在 Codex 首轮冷启动**：要 8–9 秒才把请求发给模型。其中账号工作区路由约 2.7 秒，ChatGPT 连接器就绪约 4.7 秒，剩下 3–4 秒原因没查明。去掉 MCP 服务、关掉 hooks 都不见效。热起来以后，第一个字约 1.9 秒，就是模型本身的速度。
3. **预热有效**：建好会话后空闲 15 秒再发首轮，第一个字从 10.2 秒降到 5.3 秒（只测了一次）。

所以 ACP 和 app-server 速度一样，选 app-server 是为了**控制权和少一层**：
- codex-acp 自己决定什么时候起进程、什么时候联网刷新登录，还会在每个会话首轮后**另跑一轮模型生成标题**，多耗用户额度。
- 已知 codex-acp 会忽略 `config.toml` 的沙箱和审批设置，而第 4 节的安全模型依赖逐会话设置沙箱。
- codex-acp 本身就建在 app-server 之上，适配器的滞后和 bug 都会继承过来。
- app-server 是 OpenAI 自己的 VS Code 插件、桌面版和网页版用的接口，官方承诺向后兼容。OpenAI 没有官方支持 ACP。
- 包体积：codex-acp 要带 Node 和一份 codex（实验里 `node_modules` 有 398 MB），见第 5 节。

这不是否定 ACP：对原生支持 ACP 的 Agent，ACP 就是最短的路，没有适配器那一层。问题只出在「给不支持 ACP 的 Agent 套一层 Node 适配器」。

### 体验的关键：常驻和预热

体验好坏取决于能不能把冷启动藏起来。Codex 实测的冷启动最明显；OpenAI 自家客户端也是这么做的：ChatGPT 桌面版常驻 app-server 进程，在开发中的 `code_mode_prewarm` 开关也是为了这个。这几条对所有后端通用：

原型实测（`crates/agent`，PR #412 的 `examples/chat.rs`，Codex 0.167.2，Terra 模型，各一次）：

| | 预热（起进程 + 登录检查 + 建会话） | 首轮：发出→第一个字 | 第二轮 |
|---|---|---|---|
| 建好会话立刻发 | 8.0 秒（`account/read` 3.5 秒，`thread/start` 4.1 秒） | 7.4 秒 | 1.3 秒 |
| 建好会话后空闲 15 秒再发 | 7.9 秒 | **4.1 秒** | 1.3 秒 |

预热放在后台、用户打开侧栏到打出第一句话之间完成，首轮等待能从十几秒降到 4 秒左右。

- **每种 Agent 整个应用只跑一个子进程**，多个窗口、多个对话共用；只起用户选中的那个 Agent。应用退出时结束它。
- **打开右侧栏就建会话预热**（Codex 是 `thread/start`，ACP 是 `session/new`）。如果上次退出时侧栏是开着的，应用启动后就在后台预热。
- **不自动生成会话标题**：用第一句话的前几个字当标题，不多跑一轮模型。
- **不连用户已经在跑的 Agent 后台进程**（例如 `codex app-server proxy`）。那是别的应用的进程，依赖它也不稳。

### 找到 Agent、锁版本

- 应用内置一张**已知 Agent 表**：名字、候选可执行文件名、后端类型（ACP / Codex / Claude）、启动参数、验证过的版本范围、安装说明链接。加一个原生支持 ACP 的 Agent 通常只要加一行。
- 从访达启动的 .app 拿不到 shell 的 PATH。按顺序找：设置里用户指定的路径、`/opt/homebrew/bin`、`/usr/local/bin`、`~/.local/bin`、npm 全局目录、mise/asdf 的 shims。Windows 上找 `.exe` / `.cmd`（`%APPDATA%\npm`、`%LOCALAPPDATA%`）。找到几个就在面板里列几个，用户选一个。
- 设置里可以手动加一个「自定义 ACP Agent」（可执行文件 + 参数），覆盖表里没有的。
- 协议和版本：
  - 每个后端只用最小子集。Codex：`initialize`、`thread/start`、`turn/start`、流式事件、`turn/interrupt`、审批请求（接口随版本变，以 `codex app-server generate-ts` 生成的定义为准）。Claude Code：stream-json 的输入消息和输出事件。ACP：`initialize`、`session/new`、`session/prompt`、`session/update`、`session/cancel`、`session/request_permission`。
  - 未知字段和未知事件一律忽略。
  - 启动时检查版本：低于最低版本提示升级；**Claude Code 的 stream-json 不是公开契约**，超出验证过的版本范围也提示，不硬跑。

## 2. 界面放在哪

- **右侧栏，按窗口开关**。工具栏按钮和快捷键切换（快捷键另定，不和现有的冲突）。宽度可以拖动，记在**本机应用级设置**里（照 `sidebar_width`），和根无关。
- **视觉**：侧栏直接放在窗口背景上，和左侧栏对称，没有面板、边框或阴影。笔记右边缘加一道和左边一样的淡阴影（`theme::shadow_note`）。
  - 这会改动 CLAUDE.md 里「笔记贴着窗口上、右、下边缘」这条结构原则。**要用户确认**（7.3）。侧栏关着的时候，外观和现在逐像素一致。
- **内容**（从上到下）：
  1. 头部：Agent 选择（列出本机找到的 Agent）和状态（未安装 / 未登录 / 预热中 / 就绪 / 出错），新对话，历史对话。
  2. 消息流：回复逐字流出；思考过程默认折叠；工具调用一行一个（「读了《周报》」「改了《待办》3 处」），点开能看参数。
  3. **改动卡片**：每轮结束后，列出这一轮改了哪些文档，每篇一个「撤销」，加一个「全部撤销」（第 3 节）。
  4. 输入框：上方是上下文标签，默认带「当前文档」；有选区时带「选区」；可以加文件夹或根。回车发送，运行中按 Esc 取消（各后端的取消接口）。
- **控件用 main 上现有的**：`ui::popover`、`ui::menu_row` 等，颜色用 `Theme::*` 语义 token。组件库还在实验阶段，暂不合入 main（2026-11-23 用户定），不等它。
- 动 `src/app.rs` 的布局之前，先找总控排期（热点文件）。界面代码放新文件（如 `src/assistant/`），`app.rs` 只加挂载点。
- **一个 Agent 都没找到时**：面板里写一句话说明这是什么，列出支持的 Agent 和各自的安装链接，加「已安装？指定位置…」按钮。不弹窗，不打扰不用 AI 的人。

## 3. 怎么读写文档

### 原则：Agent 不直接碰文件，一律走 `quiet` / `Store`

- 正文是 DocxXML。让 Agent 像改代码一样改 XML，容易写坏，还会和编辑器里打开的内容冲突。
- `quiet` 已经提供了按结构定位块、格式保持合法、移动时改写链接、写锁、原子写、版本快照这一套（CLI.md 原则 1、5）。AI 助手直接复用，**新能力只加一处**（`Session::call`）。

### 做法

1. 建会话时，把 **`quiet mcp`** 配成这个会话的 MCP 服务。MCP 是各家 Agent 都支持的工具接口，所以文档工具和接哪个 Agent 无关：ACP 在 `session/new` 里直接传 `mcpServers`；Codex 用 `thread/start` 的配置覆盖；Claude Code 用 `--mcp-config` 和 `--strict-mcp-config`（只用我们给的，不加载用户自己配的）。具体字段在原型里核实。
   - `quiet` 随应用一起发（#396 已经把它加进 release、Windows 安装包和 Linux 包）。应用用自己包里的那一份，不依赖 PATH。
   - 启动时带上范围：`--root <key>`，或者限定一组根（见第 4 节「范围」）。
2. Agent 读写都调用 `quiet` 的工具。写入走 `Store`：拿写锁、原子写、**每次保存都存版本快照**。
3. 应用这边：
   - 打开着、且没有未保存改动的文档，照现有机制自动载入外部写入（`Store::refresh_external`，#396 加的，同步 1c 也用它）。
   - 打开着、有未保存改动的文档：CLI 的写入以版本冲突失败（`--expect-rev`），Agent 拿到错误，告诉用户先保存。**不静默覆盖。**
4. **撤销**：改动卡片里的「撤销」就是恢复到这一轮之前的版本快照（`quiet restore` 同一条路径）。整轮的改动可以一次撤销，不需要逐步 ⌘Z。
5. `quiet` 的 MCP 现在只有两个工具：`quiet`（任意命令行）和 `quiet_run`（脚本）。这对 Agent 已经够用，省 token，也不用为助手另写一套工具。

### 为什么不在应用进程里直接提供工具、经 `editor::Core` 改

那样一次 AI 修改可以并进编辑器的 ⌘Z，但要在应用里再实现一遍 `quiet` 的全部操作，还只对打开着的文档有效。走 `quiet` + 版本快照：
- 同一套代码同时服务终端里的 Codex / Claude Code 和右侧栏，行为一致，测试一处；
- 没打开的文档、跨文档、跨根的操作都一样；
- 撤销粒度是「这一轮 AI 改了什么」，比逐步 ⌘Z 更符合用户的预期。

如果以后要「先看 diff 再确认」（7.2），用 `quiet` 已有的 `--dry-run`：写操作先只出 diff，面板里显示，用户点「应用」后再真正写。

### 和同步、多根的关系

- AI 的写入就是普通保存，iCloud / Git 同步把它当成任何一次编辑处理，不需要特殊路径。写锁保证不会和同步的三方合并同时写一个文件。
- 根由 `quiet` 按本机 `roots.json` 找（#396 的多根支持），和应用看到的完全一样。
- **对话记录不写进任何根**：它属于本机，放应用数据目录（各 Agent 自己也会存一份，例如 Codex 的 `~/.codex`）。这样根文件夹不会被 AI 的过程数据弄脏，同步也不会把对话推到别的设备。

## 4. 权限和安全

| 风险 | 做法 |
|---|---|
| 凭据 | **应用不碰任何凭据**：不读也不存 `~/.codex/auth.json`、Claude 的钥匙串项等。登录、刷新都由各 Agent 自己处理；没登录就提示用户按那个 Agent 的方式登录（7.4 讨论更小白的做法）。Claude 的订阅问题见下一行。 |
| Claude 订阅 | Agent SDK 文档写明：除非事先获批，第三方不能提供 claude.ai 登录，也不能让产品使用用户的订阅额度；用户自己登录原版 Claude Code 是允许的。应用调用用户已登录的 `claude` 走的是谁的额度，属于灰色地带。所以 **Claude 先只支持 API key**（`ANTHROPIC_API_KEY`，由用户在 Claude Code 自己的配置里设，应用不经手），订阅模式等向 Anthropic 确认后再开（7.5）。 |
| Agent 执行命令、直接改文件 | 工作目录是应用数据目录下一个空的临时文件夹（不是文档库）。能设沙箱的设成**只读沙箱**（Codex 的 sandbox；Claude Code 用 `--allowedTools` 只放 `quiet` 的 MCP 工具、`--disallowedTools` 关掉 Bash/Edit/Write）。收到命令执行或文件修改的审批请求时**一律拒绝**（ACP 的 `session/request_permission` 选拒绝），面板里显示一行「已拒绝」。ACP 客户端**不提供** `fs/write_text_file` 和终端能力，`fs/read_text_file` 也不提供。Agent 只能通过 `quiet` 的工具碰文档。做不到这些的 Agent 不进已知 Agent 表。 |
| 范围 | 默认只开放**当前文档所在的根**。在面板里可以扩大到全部根，选择记在本机。`quiet mcp` 启动时就限定好范围，Agent 越不过去。 |
| 文档里的提示注入 | 文档内容可能夹带「删掉所有文件」之类的指令。删除只进回收站（根自己的 `.quiet/` 回收站，可恢复），每一轮的改动都列在卡片里，可以一次撤销。批量删除、跨文件夹移动超过一定数量时，先出 diff 让用户确认。 |
| 隐私 | 第一次使用时提示一句：内容会发给你选的 Agent 所连的服务，按你自己的账号计费。应用本身不新增任何网络请求。CLI 的匿名使用统计照旧只计命令名，遵守应用的自动更新开关和 `DO_NOT_TRACK`。 |
| 额度 | 不自动跑额外的模型轮次：不生成标题，预热只建会话、不发消息。 |

## 5. 包体积

| 东西 | 大小 | 处理 |
|---|---|---|
| 现在的应用（macOS arm64，0.1.11） | 可执行文件约 39 MB | — |
| 各 Agent 本体 | Codex 约 270 MB（Homebrew 0.167.2） | **一个都不打包**，用用户自己装的 |
| Node 运行时、npm 适配器 | codex-acp + Node + 自带 codex 约 400 MB | **不内置**。需要 Node 适配器的 Agent 只用用户已装的或独立二进制 |
| `quiet` 命令行 | 几 MB（含 QuickJS） | 已经随应用发 |
| 三个后端的客户端 | 都是 stdio 上的 JSON（JSON-RPC 或按行 JSON），用已有的 `serde_json` 和标准库进程管理 | 不加新依赖 |
| ACP 官方 crate `agent-client-protocol` | — | 先自己实现最小子集；做 ACP 后端时比较一下 crate 的依赖（是否拉进 async 运行时），轻就用、重就不用 |

Agent 层放新 crate **`crates/agent`**，不依赖 GPUI，只依赖 `serde`/`serde_json`：负责 `Backend` 接口、已知 Agent 表、找可执行文件、三个后端的协议、会话状态和预热。它和 `fdl_core` 一样可以脱离界面测试：每个后端配一个假的 Agent 进程跑协议测试。

## 6. 对照五条原则

| 原则 | 这个方案 |
|---|---|
| 长期能扩展到 iCloud 和 GitHub 同步 | AI 的写入是普通保存，走 `Store` 的锁和版本快照，同步不需要知道 AI 的存在。对话记录不进根，不会同步出去。 |
| 所有根平等 | 读写都经 `quiet` 的多根支持，没有「默认库」特殊对待；范围按根选。 |
| 文件夹自包含 | AI 不在根里写任何自己的状态；撤销靠根自己的版本历史和回收站，跟着文件夹走。 |
| 少依赖、控制包体积 | 不打包任何 Agent、不带 Node，ACP crate 视依赖再定。新增代码是几个小的协议客户端，加上面板界面。 |
| 小白优先 | 装好任一支持的 Agent 的人打开侧栏就能用，不用配置 MCP、不用改各家的配置文件。没装的人看到一句说明和链接。**但「必须先装命令行、在终端登录」本身对小白不友好**，见 7.4。 |

## 7. 要拍板的问题

已定（2026-11-23）：从一开始按多 Agent 设计；ACP 作为通用后端，Codex（app-server）和 Claude Code（stream-json）作为原生后端；不内置 Node；应用不碰凭据；Claude 先只支持 API key。

1. **第一批接哪几个**：推荐 Codex（原生）+ 一个原生 ACP 的 Agent（Gemini CLI）一起做，这样第一版就验证了统一接口对两类后端都成立；Claude Code 第二批（等 7.5）。
2. **AI 改文档的方式**：
   - **(推荐)** 直接写，每轮结束列出改动、可以一次撤销。批量删除和大范围移动先确认。
   - 每次都先出 diff，用户确认后才写。更稳，但每一步都要点，聊天节奏会断。
   - 也可以做成面板里的一个开关，默认值二选一。
3. **右侧栏和「笔记贴右边缘」**：侧栏开着时，笔记右边缘离开窗口边，加一道对称的淡阴影（推荐）？侧栏关着时外观不变。这需要在 CLAUDE.md 的结构原则里补一条例外。
4. **小白怎么用上**：
   - 第一版只支持「用户自己装好、登录好 Agent」，面板里列出支持的 Agent 和安装链接（推荐先这样，零成本）。
   - 以后可以在面板里代为启动 Agent 自己的浏览器登录流程（由 Agent 完成，我们不碰凭据），省掉终端那一步。
   - 更远：内置 AI（自带 key 或本地模型），甚至应用自己的订阅。那需要账号体系和费用，等有用户量再说。
5. **Claude 订阅**：要不要正式向 Anthropic 询问「应用调用用户自己登录的 Claude Code、用其订阅额度」是否允许？问到之前只支持 API key。
6. **安全底线的例外**：有的 Agent 做不到「只读、不能执行命令」（没有沙箱、也不走审批）。推荐一律不接；还是允许用户在设置里明确放开、以受限模式使用？
7. **默认范围**：当前文档所在的根（推荐），还是全部根？
