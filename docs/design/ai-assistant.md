# 右侧栏 AI 助手：设计（草案，待定方向）

状态：**讨论稿**，还没有动代码。第 7 节列出要用户拍板的问题，定了再实现。

目标：在应用右侧加一个 AI 助手面板，用**用户自己的** Codex（以后也可以接别的 Agent）读、找、改文档库里的内容。应用不付模型费用，也不经手用户的账号凭据。

依据：
- 「右侧栏 AI 助手集成」会话的讨论和实验（2026-11-22）：实验在分支 `exp/acp-latency` 的 `experiments/acp-latency/`，README 里有完整数据。
- 社区对 ACP 的评价调研（同一会话，2026-11，来源是 Hacker News、各项目 GitHub issue、Zed 和 OpenAI 的博客与文档；Reddit 和 X 没能访问）。
- `quiet` 命令行（PR #396，`docs/design/CLI.md`）。
- 多根工作区（`docs/design/workspaces.md`）。

## 1. 接哪些 Agent，用什么协议

### 结论

| 阶段 | Agent | 接法 |
|---|---|---|
| 第一版 | Codex（用户本机装好、自己登录的） | 直接接 **`codex app-server`**（JSON-RPC over stdio），不走 ACP |
| 以后 | 其他 Agent（Gemini CLI 等长尾） | ACP 后端兜底，等 ACP v2 稳定再做 |
| 以后，另议 | Claude Code | 只能调用户自己登录的 `claude` 命令行；授权政策先核实（见 7.5） |
| 以后，另议 | 内置 AI（自带 key / 本地模型） | OpenAI 兼容接口；见 7.4 |

应用内部定义**自己的** Agent 接口：会话、流式消息、工具调用、审批、取消。不把任何一家的协议当内部模型，后端可以换。

### 为什么 Codex 不走 ACP

实验数据（6 轮中位数，M 系列 Mac）：

| | 直接用 app-server | ACP（codex-acp 2.9.0） |
|---|---|---|
| 启动到首轮第一个字 | 约 11.0 秒 | 约 11.1 秒 |
| 第二轮：发出到第一个字 | 1.84 秒 | 1.92 秒 |

1. **ACP 本身不慢**：探针拆出来，进出 codex-acp 各 1–2 毫秒，多一层 Node 进程启动约慢 80 毫秒。
2. **慢在 Codex 首轮冷启动**：要 8–9 秒才把请求发给模型。其中账号工作区路由约 2.7 秒，ChatGPT 连接器就绪约 4.7 秒，剩下 3–4 秒原因没查明。去掉 MCP 服务、关掉 hooks 都不见效。热起来以后，第一个字约 1.9 秒，就是模型本身的速度。
3. **预热有效**：建好会话后空闲 15 秒再发首轮，第一个字从 10.2 秒降到 5.3 秒（只测了一次）。

所以 ACP 和 app-server 速度一样，选 app-server 是为了**控制权和少一层**：
- codex-acp 自己决定什么时候起进程、什么时候联网刷新登录，还会在每个会话首轮后**另跑一轮模型生成标题**，多耗用户额度。
- 已知 codex-acp 会忽略 `config.toml` 的沙箱和审批设置，而第 4 节的安全模型依赖逐会话设置沙箱。
- codex-acp 本身就建在 app-server 之上，适配器的滞后和 bug 都会继承过来。
- app-server 是 OpenAI 自己的 VS Code 插件、桌面版和网页版用的接口，官方承诺向后兼容。OpenAI 没有官方支持 ACP。
- 包体积：codex-acp 要带 Node 和一份 codex（实验里 `node_modules` 有 398 MB），见第 5 节。

ACP 的已知问题：v1 不能在 Agent 运行中途插话，不能单独取消，长会话回放不全，审批信息不完整。v2 在 2026-11-20 出了 Preview，专门修这些。等 v2 稳定后，ACP 适合用来接长尾 Agent。

### 体验的关键：常驻和预热

体验好坏取决于能不能把冷启动藏起来。OpenAI 自家客户端也是这样做的：ChatGPT 桌面版常驻 app-server 进程，在开发中的 `code_mode_prewarm` 开关也是为了这个。

- **整个应用只跑一个 app-server 子进程**，多个窗口、多个对话共用。应用退出时结束它。
- **打开右侧栏就 `thread/start` 预热**。如果上次退出时侧栏是开着的，应用启动后就在后台预热。
- **不自动生成会话标题**：用第一句话的前几个字当标题，不多跑一轮模型。
- **不连用户已经在跑的 Codex 后台进程**（`codex app-server proxy`）。那是别的应用的进程，依赖它也不稳。

### 找到 codex

- 从访达启动的 .app 拿不到 shell 的 PATH。按顺序找：设置里用户指定的路径、`/opt/homebrew/bin`、`/usr/local/bin`、`~/.local/bin`、npm 全局目录、mise/asdf 的 shims。Windows 上找 `codex.exe` / `codex.cmd`（`%APPDATA%\npm`、`%LOCALAPPDATA%`）。
- app-server 的接口和 Codex 版本绑定（`codex app-server generate-ts` 生成的定义随版本变）。做法：
  - 只用一个最小子集：`initialize`、`thread/start`、`turn/start`、流式事件、`turn/interrupt`、审批请求。
  - 未知字段和未知事件一律忽略。
  - `initialize` 时检查版本，低于最低版本就提示用户升级，不硬跑。

## 2. 界面放在哪

- **右侧栏，按窗口开关**。工具栏按钮和快捷键切换（快捷键另定，不和现有的冲突）。宽度可以拖动，记在**本机应用级设置**里（照 `sidebar_width`），和根无关。
- **视觉**：侧栏直接放在窗口背景上，和左侧栏对称，没有面板、边框或阴影。笔记右边缘加一道和左边一样的淡阴影（`theme::shadow_note`）。
  - 这会改动 CLAUDE.md 里「笔记贴着窗口上、右、下边缘」这条结构原则。**要用户确认**（7.3）。侧栏关着的时候，外观和现在逐像素一致。
- **内容**（从上到下）：
  1. 头部：Agent 名字和状态（未安装 / 未登录 / 预热中 / 就绪 / 出错），新对话，历史对话。
  2. 消息流：回复逐字流出；思考过程默认折叠；工具调用一行一个（「读了《周报》」「改了《待办》3 处」），点开能看参数。
  3. **改动卡片**：每轮结束后，列出这一轮改了哪些文档，每篇一个「撤销」，加一个「全部撤销」（第 3 节）。
  4. 输入框：上方是上下文标签，默认带「当前文档」；有选区时带「选区」；可以加文件夹或根。回车发送，运行中按 Esc 取消（`turn/interrupt`）。
- **控件用 main 上现有的**：`ui::popover`、`ui::menu_row` 等，颜色用 `Theme::*` 语义 token。组件库还在实验阶段，暂不合入 main（2026-11-23 用户定），不等它。
- 动 `src/app.rs` 的布局之前，先找总控排期（热点文件）。界面代码放新文件（如 `src/assistant/`），`app.rs` 只加挂载点。
- **没装 Codex 时**：面板里写一句话说明这是什么，给一个「安装 Codex」的链接和「已安装？指定位置…」按钮。不弹窗，不打扰不用 AI 的人。

## 3. 怎么读写文档

### 原则：Agent 不直接碰文件，一律走 `quiet` / `Store`

- 正文是 DocxXML。让 Agent 像改代码一样改 XML，容易写坏，还会和编辑器里打开的内容冲突。
- `quiet` 已经提供了按结构定位块、格式保持合法、移动时改写链接、写锁、原子写、版本快照这一套（CLI.md 原则 1、5）。AI 助手直接复用，**新能力只加一处**（`Session::call`）。

### 做法

1. 应用启动 app-server 会话时，把 **`quiet mcp`** 配成这个会话的 MCP 服务（`thread/start` 的配置覆盖；具体字段在第一步原型里核实）。
   - `quiet` 随应用一起发（#396 已经把它加进 release、Windows 安装包和 Linux 包）。应用用自己包里的那一份，不依赖 PATH。
   - 启动时带上范围：`--root <key>`，或者限定一组根（见第 4 节「范围」）。
2. Agent 读写都调用 `quiet` 的工具。写入走 `Store`：拿写锁、原子写、**每次保存都存版本快照**。
3. 应用这边：
   - 打开着、且没有未保存改动的文档，照现有机制自动载入外部写入（`Store::refresh_external`，#396 加的，同步 1c 也用它）。
   - 打开着、有未保存改动的文档：CLI 的写入以版本冲突失败（`--expect-rev`），Agent 拿到错误，告诉用户先保存。**不静默覆盖。**
4. **撤销**：改动卡片里的「撤销」就是恢复到这一轮之前的版本快照（`quiet restore` 同一条路径）。整轮的改动可以一次撤销，不需要逐步 ⌘Z。
5. `quiet` 的 MCP 现在只有两个工具：`quiet`（任意命令行）和 `quiet_run`（脚本）。这对 Agent 已经够用，省 token，也不用为助手另写一套工具。

### 为什么不在应用进程里直接提供工具、经 `editor::Core` 改

那样一次 AI 修改可以并进编辑器的 ⌘Z，但要在应用里再实现一遍 `quiet` 的全部操作，还只对打开着的文档有效。走 `quiet` + 版本快照：
- 同一套代码同时服务终端里的 Codex / Claude Code 和右侧栏，行为一致，测试一处；
- 没打开的文档、跨文档、跨根的操作都一样；
- 撤销粒度是「这一轮 AI 改了什么」，比逐步 ⌘Z 更符合用户的预期。

如果以后要「先看 diff 再确认」（7.2），用 `quiet` 已有的 `--dry-run`：写操作先只出 diff，面板里显示，用户点「应用」后再真正写。

### 和同步、多根的关系

- AI 的写入就是普通保存，iCloud / Git 同步把它当成任何一次编辑处理，不需要特殊路径。写锁保证不会和同步的三方合并同时写一个文件。
- 根由 `quiet` 按本机 `roots.json` 找（#396 的多根支持），和应用看到的完全一样。
- **对话记录不写进任何根**：它属于本机，放应用数据目录（会话本身 Codex 也存在 `~/.codex`）。这样根文件夹不会被 AI 的过程数据弄脏，同步也不会把对话推到别的设备。

## 4. 权限和安全

| 风险 | 做法 |
|---|---|
| 凭据 | 不读也不存 `~/.codex/auth.json`。登录、刷新都由 Codex 自己处理；没登录就提示用户在终端运行 `codex login`（7.4 讨论更小白的做法）。 |
| Agent 执行命令、直接改文件 | 每个会话设成**只读沙箱**，工作目录是应用数据目录下一个空的临时文件夹（不是文档库）。应用收到命令执行或文件修改的审批请求时**一律拒绝**，在面板里显示一行「已拒绝」。Agent 只能通过 `quiet` 的工具碰文档。 |
| 范围 | 默认只开放**当前文档所在的根**。在面板里可以扩大到全部根，选择记在本机。`quiet mcp` 启动时就限定好范围，Agent 越不过去。 |
| 文档里的提示注入 | 文档内容可能夹带「删掉所有文件」之类的指令。删除只进回收站（根自己的 `.quiet/` 回收站，可恢复），每一轮的改动都列在卡片里，可以一次撤销。批量删除、跨文件夹移动超过一定数量时，先出 diff 让用户确认。 |
| 隐私 | 第一次使用时提示一句：内容会发给你的 Codex 所连的服务，按你自己的账号计费。应用本身不新增任何网络请求。CLI 的匿名使用统计照旧只计命令名，遵守应用的自动更新开关和 `DO_NOT_TRACK`。 |
| 额度 | 不自动跑额外的模型轮次：不生成标题，预热只建会话、不发消息。 |

## 5. 包体积

| 东西 | 大小 | 处理 |
|---|---|---|
| 现在的应用（macOS arm64，0.1.11） | 可执行文件约 39 MB | — |
| Codex 本体 | 约 270 MB（Homebrew 0.167.2） | **不打包**，用用户自己装的 |
| codex-acp + Node + 自带 codex | 约 400 MB | **不用** |
| `quiet` 命令行 | 几 MB（含 QuickJS） | 已经随应用发 |
| app-server 客户端 | JSON-RPC over stdio，用已有的 `serde_json` 和标准库进程管理 | 不加新依赖 |
| ACP | Rust 官方 crate `agent-client-protocol` | 第一版不加，做 ACP 后端时再加 |

Agent 层放新 crate **`crates/agent`**，不依赖 GPUI，只依赖 `serde`/`serde_json`：负责进程管理、找 codex、协议、会话状态和预热。它和 `fdl_core` 一样可以脱离界面测试：用一个假的 app-server 脚本跑协议测试。

## 6. 对照五条原则

| 原则 | 这个方案 |
|---|---|
| 长期能扩展到 iCloud 和 GitHub 同步 | AI 的写入是普通保存，走 `Store` 的锁和版本快照，同步不需要知道 AI 的存在。对话记录不进根，不会同步出去。 |
| 所有根平等 | 读写都经 `quiet` 的多根支持，没有「默认库」特殊对待；范围按根选。 |
| 文件夹自包含 | AI 不在根里写任何自己的状态；撤销靠根自己的版本历史和回收站，跟着文件夹走。 |
| 少依赖、控制包体积 | 不打包 Codex、不带 Node、不加 ACP crate。新增代码只有一个小的协议客户端，加上面板界面。 |
| 小白优先 | 装好 Codex 的人打开侧栏就能用，不用配置 MCP、不用改 `config.toml`。没装的人看到一句说明和链接。**但「必须先装命令行、在终端登录」本身对小白不友好**，见 7.4。 |

## 7. 要拍板的问题

1. **Codex 接法**：直接用 `codex app-server`（推荐），还是走 ACP（codex-acp）？推荐理由在第 1 节：速度一样，app-server 少一层、可控、没有额外额度开销、不需要 Node。
2. **AI 改文档的方式**：
   - **(推荐)** 直接写，每轮结束列出改动、可以一次撤销。批量删除和大范围移动先确认。
   - 每次都先出 diff，用户确认后才写。更稳，但每一步都要点，聊天节奏会断。
   - 也可以做成面板里的一个开关，默认值二选一。
3. **右侧栏和「笔记贴右边缘」**：侧栏开着时，笔记右边缘离开窗口边，加一道对称的淡阴影（推荐）？侧栏关着时外观不变。这需要在 CLAUDE.md 的结构原则里补一条例外。
4. **小白怎么用上**：
   - 第一版只支持「用户自己装 Codex 并登录」，面板里给安装链接（推荐先这样，零成本）。
   - 以后可以在面板里代为启动 `codex login` 的浏览器登录流程（由 Codex 自己完成，我们不碰凭据），省掉终端那一步。
   - 更远：内置 AI（自带 key 或本地模型），甚至应用自己的订阅。那需要账号体系和费用，等有用户量再说。
5. **Claude Code**：Anthropic 不允许第三方应用提供 Claude 订阅登录（Zed 里的 Claude 只能填 API key）。调用用户自己登录的 `claude` 命令行是否合规，要先核实政策再决定做不做。
6. **默认范围**：当前文档所在的根（推荐），还是全部根？

## 8. 落地顺序（定了方向以后）

0. **CLI #396 合入**，带多根支持（进行中）。
1. **`crates/agent` 原型**，不碰界面：
   - 找 codex、起 app-server、`initialize`、`thread/start`（只读沙箱、临时工作目录、`quiet mcp` 作为 MCP 服务）、`turn/start` 流式、取消、自动拒绝审批；
   - 常驻加预热；
   - 用一个小的命令行入口实测「预热后首轮第一个字」（原会话还没测这一组），只用我们自己起的进程；
   - 测 Codex 时只用 Terra 模型。
2. **右侧栏界面**：用现有控件，动 `src/app.rs` 前和总控排好时间。消息流、输入框、上下文标签、状态。
3. **改动卡片和撤销**：每轮记下改了哪些文档和改之前的版本，接 `quiet restore`。
4. 之后按需要：先确认模式（`--dry-run`）、ACP 后端、Claude Code、内置 AI。

每一步一个 PR。第 1 步只加新 crate，不碰热点文件。
